About

def about_me():

I'm a Senior Software Engineer at Sun Creature in Copenhagen, and I've worked in animation, film and games for 7+ years. I build Python tools and services that move production data between ShotGrid, the file server and the people who use them.

I led the studio's move from scattered spreadsheets to one shared source of truth in ShotGrid, without stopping production. Most of my users are artists and producers. I want artists to focus on the creative work and producers on their teams, schedules and budgets. That only works if the data is easy to find, read and use. I also script for the tools artists use every day, like Maya, Blender, Adobe CC, TVPaint and Toon Boom Harmony.

I care a lot about doing right by the people I work with. I document things properly, I communicate early, and I make sure nobody gets stuck waiting on me. I've been lucky enough to ship work for Netflix, Blizzard, Disney, Riot Games, Supercell, EA, The LEGO Group and others.

Data project

cd ~/legacy-to-lakehouse

A practice data migration with made-up data, based on the one I did at work. Three productions tracked their shots in their own spreadsheets: an Excel file, a Google Sheet and a Coda doc. Different columns, status spellings and date formats, plus duplicates and blanks. The pipeline moves all of it into one Delta Lake table and proves nothing was lost.

1. Bronze
Each export lands as-is, all as text, with where and when it came from.
2. Silver
Each source is mapped and cleaned into one table. MERGE means a rerun updates shots instead of duplicating them.
3. Quarantine
Rows that can't be fixed are kept with a reason, so nothing is dropped silently and nothing is guessed.
4. Reconcile
Counts every shot in the legacy files and fails the build if one is missing or invented.

Result: 240 legacy shots, 216 in the new table, 24 in quarantine, 0 missing. 23 tests, and GitHub Actions runs the whole migration on every push. Next: running it in PySpark on Databricks.
